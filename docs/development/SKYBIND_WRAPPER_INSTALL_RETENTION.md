# Skybind local build: optional KernelSU install and one-build retention

This source-bound patch applies to the **repository `./devtoolw` local and personal build workflows**.
It does not alter the Devtool runtime or claim a formal release gate.

## Commands

```sh
./devtoolw build -i                   # NewFuture candidate, then install it
./devtoolw build --install
./devtoolw build-newfuture -i
./devtoolw build-bclone --install
./devtoolw personal-release -i        # bclone personal ZIP, exported to Downloads first
./devtoolw personal-release-newfuture --install
./devtoolw build-both                 # build both; no auto-install
```

Without `-i`/`--install`, commands only build; no root operation is attempted.
`build-both -i` fails immediately instead of choosing one of two providers silently.
The wrapper's thin flag dispatcher maps the opt-in flag to named Devtool workflow
jobs, so Devtool remains the build runner and all its normal logs and failure
handling are retained. The `devtoolw` launcher is generated by Devtool; if
`devtool wrapper update` regenerates it, reapply/reconcile the repository-owned
flag dispatcher. No external Devtool runtime files are changed.

## Installer contract

After a verified, single-provider module ZIP exists, the build invokes:

```sh
su -c 'ksud module install /absolute/path/to/the/verified.zip'
```

The real implementation quotes paths, passes a fixed command as a single argv
item to `su -c`, and inherits **both stdout and stderr** (no redirects or
silent capture). This allows installer progress on stderr to appear alongside
stdout. A nonzero exit returns an overall build workflow failure, and the
newly built ZIP is retained for investigation. There is no automatic reboot.
An exit code 0 means `ksud` accepted the installation command; runtime/device
acceptance, activation on reboot, and formal release qualification remain
separate. No arbitrary ZIP path can be injected via wrapper arguments.

## Automatic old-build cleanup

Only after a new candidate ZIP and its evidence receipt have been verified,
older managed `dist/local-candidates/candidate-*` folders are deleted.
A newly published personal build also prunes older recognized
`/storage/emulated/0/Download/Skybind-Personal-*` export directories.

Retention is **one newest candidate build and one newest personal export**.
Previously kept results from other providers count as older builds.
Cleanup only considers directories with the expected Skybind-specific names,
receipt identity, and complete known file layouts. It skips symlinks, foreign
files, modified folders, and suspicious/missing receipts rather than deleting
unknown data. Original Q04 provider evidence caches and any diagnostic,
qualification, remote, runtime, and release provenance files remain untouched.
Failed builds never prune earlier artifacts. The newly built ZIP remains
available even if `ksud` fails.

## Limitations

* Local candidates are **unqualified** and remain `CANDIDATE_ONLY_NOT_SEALED`.
* Local Go compiler pins, provider provenance, and verifier are unchanged.
* Auto-install uses root and may change the KernelSU module state. Run only
  when you intend to install; reboot manually when appropriate.
* A generated launcher regeneration may replace the install-flag dispatcher.
* The installer is tested with mocks on the host; an actual `ksud` invocation
  and installation progress still require physical Android qualification.
