# R1 trusted consumer admission and next live-device boundary

**Status:** source-implemented; BKX platform PackageManager probe is implemented in the instrumentation APK, not yet run. **No live Android-to-Go PM authority channel, external listener, grants or BKX/chrootctl gateway runtime is production-qualified.** The four M3 source-bound device scopes remain passing independently; this package does not rerun them.

## Source-owned components and invariants

- `internal/brokerruntime.Policy` is one strict operator-approved schema, *not* a consumer request. `LoadAt` requires root ownership, private 0700 parent, 0600 regular nlink=1 file, bounded content, no symlink, no duplicate JSON keys, unknown fields or trailing input. Both consumers have explicit signer/seal and SELinux pins, with an independently selected UID, remote segment prefix and a set of approved read-only operations. 5 minute maximum token TTL; no `sync`, `rcat`, arbitrary shell or Restic.
- `Gateway.Assemble` composes the EXISTING `brokeridentity`, `brokeripc`, `brokergrant`, and `brokerissue` packages. The Android PackageManager authority, trusted `/proc` reader, installed-module attestor and typed read-only backend must **all** be injected; any missing authority fails closed. Neither package names nor binary versions create grants. BKX updates do not force a Skybind rebuild; changed signer/module seals require operator review/reapproval and revocation.
- `Gateway.IssueApproved` is deliberately not exposed over the consumer socket and only accepts an exact operator-authorized scope and verified live process incarnation. `Gateway.Revoke` invalidates credentials; new process incarnation is not an existing grant. The socket from the previous overlay is never started from the ordinary daemon or module service.
- Android `R1BKXInstalledPackageAcceptanceTest` uses actual Android PackageManager API on a GitHub-built APK to check BKX UID, one installed package and independently approved signer digest, plus wrong-signer denial. The manifest adds only BKX's package visibility; no QUERY_ALL_PACKAGES and no exported authority. **PM-only observation does not authenticate a Go peer or authorize external use.**
- `scripts/dev/android/r1_bkx_pm_device.py` performs exact hosted source/signing/installed APK pair verification before invoking the one opt-in PM test. It never installs APKs or issues grants. It writes a 0600 receipt whose true statement is **`PASS_R1_BKX_PLATFORM_PM_OBSERVATION_ONLY`** at most. Its `external_provider_qualified` and `release_qualified` always remain false.

## Device procedure and missing dependencies

The first on-device step is to build the new instrumentation APK *on GitHub*, then use the existing approved same-signer installation mechanism (no repeat M3 tests). To run the PM-only test, an operator must separately approve the observed BKX signing certificate SHA-256 (digest of DER) and current UID; **never silently derive a trusted pin from the consumer's own request or this repository**. BKX is currently observed as `com.mikeyphw.bkx.android`, UID `10327`, version 1.0.0, but this is untrusted discovery evidence, not a permanent authorization pin. Use `--serial emulator-5554` and a new exact `$RUN_ID`; `r1_bkx_pm_device.py` is read-only and refuses a nonmatching installed pair. chrootctl 1.3.7's root-owned manifest/runtime hashes are similarly *observations*, not operator approval.

Real R1 cross-process qualification remains **BLOCKED** until a trusted Android PackageManager authority can deliver non-consumer-asserted observations to Go, a separately approved chrootctl module-process seal/SELinux identity is observed for a real active PID, and a privileged control plane provisions and transmits narrowly scoped grants to the genuine consumer. Only after then may an explicitly activated read-only listener undergo live tests for non-owned remote denial, revocation, PID reuse, changed signer/module seal, and root-app impersonation. In particular, an app that has never integrated a broker client cannot magically issue its own broker requests; BKX/chrootctl adapters must be introduced independently and accepted. Keep their native rclone runtimes available. R2 metadata, R3 streams, and R5 Restic remain unimplemented.

## Source-only acceptance

Run `./devtoolw r1-trust-admission-source`. GitHub's `skybind-source.yml` also runs new Go and Python negative tests. The hosted `skybind-android-apks.yml` must compile the new Kotlin test before trying any device PM observation. A source PASS is not a real-device or release PASS. No module install, root-grant mutations, BKX backup or chrootctl archive actions are part of this overlay.
