# R1 independent consumer adapters, metadata, grant handoff and root gateway

**Scope: source implementation only; real BKX/chrootctl consumer IPC and Android SELinux acceptance are not qualified.** The Android-to-Go PackageManager authority channel previously passed seven independent cases (`PASS_R1_ANDROID_TO_GO_PM_THREE_CASES_PLUS_FOUR_AGENT_NEGATIVES`) for source `7ba88071f6e3446316948c4789c80d33be7963ee`. That historical receipt remains valid **only for the narrow PM bridge**, and M3 device PASS scopes remain untouched.

## Implemented here

- `brokerruntime.Metadata.Read` uses Skybind's existing bounded provider and canonical root config. The fixed read-only set is `system.capabilities`, `rclone.version`, `rclone.listremotes`, `rclone.lsjson`, `rclone.size`. The backend uses fixed typed rclone CLI arguments, not `sh`, arbitrary RC, caller-supplied flags or env. ListRemotes discloses only the independently approved grant's remote name, not all remotes, types or rclone configuration. Paths and names reject option injection, traversal, colon and control characters; size counters and version are parsed and bounded; failures do not reveal stderr.
- `brokerruntime.GrantHandoff` is a different abstract socket. An explicitly running **root operator** supplies the real process PID, exact consumer, remote/prefix, operation and TTL under a root-owned policy; the gateway binds an offer to `ConsumerVerifier.VerifyPeer`'s exact process key and kernel `UID/GID/PID`. The client requests no scope or tokens, and receives a one-time random 256-bit grant over the attested peer connection. Unclaimed offers expire after 30 seconds and mint no token. The operator can list receipt IDs (not tokens), revoke grants immediately, and all outstanding grants are revoked on shutdown. No token is logged or persisted. The data socket rechecks the identity and authorizes before invoking the backend.
- `cmd/skybind-r1-gateway` is an **interactive, opt-in root diagnostic**, never a service script. It loads mode-0600 operator policy from root-owned 0700 directory, waits for the existing Android-to-Go PackageManager agent, starts the abstract consumer socket and grant handoff, and accepts only local-operator commands `approve PID consumer REMOTE PREFIX OP TTL_SECONDS`, `receipts`, `revoke ID`, `quit`. It requires explicit `--operator-approve` and separately approved authority-app UID, SELinux context and installed APK byte digest.
- `AuthorityAPKAnchor` checks the exact **operator-approved installed APK bytes** from a system/root-owned, non-writable canonical `/data/app/.../base.apk` pathname, before accepting the PM agent and during later requests. It is independent of statements returned by that agent. **It does NOT cryptographically validate the APK signer** or independently prove the running process loaded those bytes; independent signer lineage is still a separate qualification obligation. Changed APK bytes fail closed until operator review/approval, not a Skybind rebuild.
- `cmd/skybind-r1-module-check` is a root-only, read-only live chrootctl **process** verifier with real `/proc/PID` identity, operator-approved SELinux context and module-package-manifest SHA-256, installed executable match/inode/digest. It requires a live already-running chrootctl binary; no process == BLOCKED. It does not run backups, issue grants or qualify provider access.
- `integrations/bkx/SkybindR1ReadClient.kt` is a drop-in Kotlin adapter **source example only**. It cannot alter the separately installed BKX APK until intentionally ported into BKX's own current source, built, deployed and device-tested. No native-rclone fallback is silently changed.
- The companion chrootctl Devtool source overlay adds the opt-in `chrootctl skybind-read --operation ... --remote ... --path ...` command and its isolated tests. Native sealed rclone and archival/backup operations are unchanged. Its executable **must be rebuilt and installed separately**; the current installed chrootctl 1.3.7 executable does not gain the command from a Skybind source update. A new module manifest seal needs independent approval after installation.

## Operator sequence (device acceptance not yet performed)

1. Qualify the hosted Skybind diagnostic binary and the installed Skybind APK/PM bridge against the same source identity. Independently review the installed Skybind APK signer certificate and the canonical package path; approve the APK SHA-256 only after comparing against the trusted signed APK artifact. Verify app UID and measured SELinux context separately. The APK byte-seal alone does not satisfy platform signing-lineage acceptance.
2. Build and qualify the chrootctl source overlay on its own GitHub CI; install only with explicit user approval. Take a new root-owned manifest hash, verify its packaged executable, and measure the live process context. Do not reuse the historical v1.3.7 module seal after upgrading.
3. Provision `/data/adb/skybind/consumer-policy-v1.json` as root:root, mode 0600, under root-owned mode-0700 `/data/adb/skybind`. Include an exact BKX signing pin, BKX UID/SELinux pin and the approved chrootctl manifest SHA/context, plus narrowly scoped rules. The policy must explicitly enable R1, but **installing it alone starts nothing**.
4. Start the hosted `skybind-r1-gateway-android-arm64` diagnostic in an operator-controlled root terminal with `--operator-approve`, `--authority-uid`, `--authority-context`, `--authority-apk`, `--authority-apk-sha256`. Bring the Skybind app to foreground so the Android PackageManager agent connects. The daemon's normal startup is not modified.
5. Start the **rebuilt** chrootctl binary in a second root shell with `chrootctl skybind-read --operation rclone.lsjson --remote REMOTE --path APPROVED_RELATIVE_PATH`. The client will wait a bounded period for the operator. From the gateway terminal issue `approve REAL_PID chrootctl REMOTE APPROVED_PREFIX rclone.lsjson 60`. The exact process must pass the existing module-seal verifier; a root shell or generic `su` process is not enough. Confirm the read, wrong-remote/traversal/write denial, live revocation, and one-time offer semantics. Inspect SELinux denials if the kernel prevents abstract-socket use; **do not weaken SELinux to force PASS**.
6. The BKX app requires its source adapter independently integrated/built/installed before its process can request a grant. Its package signer, UID and process label must match the approved policy. No native-rclone fallback change is made here.

## Qualification contract

A full consumer provider qualification must include, per installed app/module and exact source pair: live kernel peer receipt, PackageManager signer check or chrootctl module seal check, SELinux socket reachability, correct grant issuance and delivery to **that exact PID**, read-only backend response, denial for wrong UID/signer/module/remote/path/write and expired or revoked grant, no token leakage or credential/mutation, and independent release gates. Until then leave `SKYBIND_CONSUMER_ABI_V1.json` at `NOT_IMPLEMENTED` and `available_external_capabilities=[]`; production listener remains opt-in and release-qualification false.

**Limitations:** No BKX current source was available in this workspace, so its adapter is a reviewed reference source, **not an APK change**. Source/host tests cannot substitute for the real Android SELinux and process-grant acceptance. Independent APK signing-lineage verification is not implemented by the byte-seal helper; approval still requires external authority, so overall external-provider qualification is BLOCKED.
